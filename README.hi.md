# amnezia-mesh

स्वयं-होस्ट किया गया WireGuard मेश, AmneziaWG ट्रैफ़िक ऑब्फ़स्केशन, MagicDNS और
Tailscale-शैली के exit/mesh प्रोफ़ाइल के साथ — एक ही VPS पर, ~10 मिनट में, और
Docker के अलावा बिना किसी निर्भरता के।

इसे «अपना खुद का Tailscale» समझिए — लेकिन जहाँ हर हॉप आपका है: एक छोटा सर्वर,
आपके उपकरणों पर Amnezia की आधिकारिक ऐप, और न तो कोऑर्डिनेशन सर्वर, न खाते, न
तृतीय-पक्ष रिले।

## विशेषताएँ

- **CGNAT मेश नेटवर्क** (`100.64.0.0/24`, RFC 6598) — हर उपकरण को एक स्थायी IP
  मिलता है; उपकरणों के बीच SSH/ping हब के माध्यम से चलता है, जैसे `tailscale ssh`।
- **AmneziaWG 3.1 ऑब्फ़स्केशन** — जंक-पैकेट हैंडशेक, हेडर टाइप प्रतिस्थापन,
  हेडर प्रोटेक्शन कुंजी, यादृच्छिक padding/trailer। पैरामीटर **हर डिप्लॉयमेंट पर
  यादृच्छिक** होते हैं, इसलिए DPI फ़िंगरप्रिंट इंस्टॉल के बीच अलग-अलग होते हैं।
- **MagicDNS** — हब पर dnsmasq `<उपकरण>.<डोमेन>` (जैसे `laptop.awg`) का उत्तर
  देता है और बाक़ी सब को टनल के माध्यम से आपके अपस्ट्रीम रिज़ॉल्वर को फ़ॉरवर्ड
  करता है।
- **प्रति उपकरण exit + mesh प्रोफ़ाइल** — `exit` सारा ट्रैफ़िक VPS से रूट करता
  है (सेंसरशिप बायपास); `mesh` सिर्फ़ CGNAT सबनेट रूट करता है और इंटरनेट सीधा
  रहता है। दोनों हर उपकरण के लिए बनाए जाते हैं।
- **Amnezia ऐप के नेटिव प्रोफ़ाइल** (`vpn://`) साथ ही किसी भी awg/wg-संगत
  क्लाइंट के लिए सादा `.conf`।
- **डिज़ाइन से संस्करण-अज्ञेय** — AWG इमेज एक बाहरी, बदली जा सकने वाली
  निर्भरता है; सारा तर्क होस्ट पर रहता है (नीचे *डिज़ाइन* देखें)।
- **एजेंट-अनुकूल CLI** — हर कमांड के पास `--json` आउटपुट, एनवायरनमेंट-वेरिएबल
  ओवरराइड और नॉन-इंटरैक्टिव मोड है।

## आवश्यकताएँ

- सार्वजनिक IP वाला VPS, compose प्लगइन के साथ Docker, और `python3`
  (>= 3.8, केवल स्टैंडर्ड लाइब्रेरी — `pip install` नहीं)।
- VPS फ़ायरवॉल में खुला UDP पोर्ट (अनुशंसित 443/udp — यह सामान्य HTTPS/QUIC
  ट्रैफ़िक में घुल मिल जाता है और ISP के लिए इसे शेप करना सबसे मुश्किल)।

## AI एजेंट के साथ सेटअप (Claude Code, Kimi Code, Cursor, …)

CLI अपना ऑपरेटर स्किल लेकर आता है — इंस्टॉल, ऑटोमेशन प्रोटोकॉल, रीस्टार्ट
सेमेंटिक्स और निदान के लिए डिसीज़न ट्री को कवर करने वाला एक संक्षिप्त रनबुक।
इसे अपने एजेंट को दें और पूरा प्रवाह बातचीत बन जाता है:

```sh
# macOS cask: awg-mesh (CLI) और awg-mesh-tui. Linux: Releases देखें.
brew tap alexpozdnyakof/tap
brew install --cask alexpozdnyakof/tap/awg-mesh
# या: इस रेपो को git clone करें

awg-mesh-tui install --ssh root@आपका_VPS --json
awg-mesh skill --install   # ~/.agents/skills/awg-mesh/SKILL.md
```

फिर बस पूछिए, जैसे: *«इस VPS (IP 203.0.113.7) पर मेरा VPN सेटअप करो, मेरा
लैपटॉप और फ़ोन जोड़ो, फिर सेल्फ़-चेक चलाओ»*। एजेंट `awg-mesh init` /
`peer add` / `doctor --json` चलाता है, बनाए गए प्रोफ़ाइल आपके उपकरणों पर
इम्पोर्ट करता है और स्किल के डिसीज़न ट्री से कनेक्टिविटी का निदान करता है।
रेपो के रूट में `AGENTS.md` चेकआउट के अंदर काम करने वाले एजेंटों के लिए वही
ओरिएंटेशन करता है।

## क्विकस्टार्ट (इंसान)

```sh
git clone https://github.com/<you>/amnezia-mesh && cd amnezia-mesh

./bin/awg-mesh init --host आपका_IP_या_डोमेन --port 443
./bin/awg-mesh peer add laptop
# → प्रिंट करता है: config/peers/laptop-exit.vpn, laptop-mesh.vpn, और .conf वेरिएंट
# .vpn लिंक को उपकरण के Amnezia ऐप में इम्पोर्ट करें

./bin/awg-mesh peer add phone
./bin/awg-mesh doctor      # इंस्टॉल के बाद सेल्फ़-चेक
./bin/awg-mesh monitoring install   # वैकल्पिक: cron आँकड़े + watchdog
```

उपकरण पर: Amnezia ऐप → `vpn://` लिंक इम्पोर्ट करें → कनेक्ट करें। अब उपकरण
एक-दूसरे को IP (`100.64.0.x`) या नाम (`phone.awg`) से पहुँच सकते हैं।

## क्विकस्टार्ट (एजेंट / ऑटोमेशन)

```sh
export AWG_MESH_NONINTERACTIVE=1
./bin/awg-mesh --json init --host 198.51.100.10 --port 443
./bin/awg-mesh --json peer add laptop
./bin/awg-mesh --json doctor        # एग्ज़िट कोड 0 = सभी चेक हरे
```

आउटपुट प्रति कमांड एक JSON ऑब्जेक्ट है; विफलता पर एग्ज़िट कोड नॉन-ज़ीरो और
`{"ok": false, "error": "..."}` मिलता है।

## कमांड

| कमांड | विवरण |
|---|---|
| `awg-mesh init [--host H] [--port P] [--subnet CIDR] [--image IMG] [--domain D] [--rdp-reject]` | कुंजियाँ + यादृच्छिक ऑब्फ़स्केशन बनाना, कॉन्फ़िग रेंडर, कंटेनर स्टार्ट |
| `awg-mesh peer add <name> [--type exit\|mesh\|both]` | नया उपकरण: कुंजियाँ, IP, प्रोफ़ाइल (लाइव `awg set` + dnsmasq SIGHUP से लागू — रीस्टार्ट नहीं; मौजूदा पीयर अपने सेशन बनाए रखते हैं) |
| `awg-mesh peer list` | उपकरण, IP, निर्माण तिथियाँ |
| `awg-mesh peer rename <name> <new-name> [pairs...]` | उपकरण का नाम बदलना — adopt के बाद बने `peer-xxxx` नामों को एक ही बार में साफ़ करने के लिए कई पुराना/नया जोड़े पास करें (MagicDNS नाम साथ चलते हैं; केवल dnsmasq SIGHUP — रीस्टार्ट नहीं; all-or-nothing वैलिडेशन, स्वैप समर्थित) |
| `awg-mesh peer rotate <name>` | उपकरण की कुंजियाँ दोबारा जारी करना (वही IP; हब revoke की तरह रीस्टार्ट होता है — उपकरण को प्रोफ़ाइल दोबारा इम्पोर्ट करना होगा, पुराना `vpn://` लिंक मर जाता है) |
| `awg-mesh peer revoke <name>` | उपकरण हटाना (awg + dns कंटेनर रीस्टार्ट होते हैं — userspace डेमॉन से UAPI द्वारा पीयर हटाने से नए हैंडशेक चुपचाप अटक सकते हैं; प्रोफ़ाइल मिट जाते हैं) |
| `awg-mesh doctor [--json]` | Docker, कंटेनर, लिसन पोर्ट, ip_forward, MagicDNS, पोर्ट पब्लिशिंग |
| `awg-mesh dns add <name> <ipv4>` / `dns remove <name>` / `dns list` | `<name>.<domain>` के ऊपर कस्टम MagicDNS रिकॉर्ड (`nas.awg` → कोई भी IPv4) `config/custom.hosts` में — dnsmasq का दूसरा `--addn-hosts`, SIGHUP से रीलोड, रीस्टार्ट नहीं |
| `awg-mesh monitoring install\|uninstall` | cron आँकड़े (`/var/log/amnezia-mesh-stats.log`) + watchdog |
| `awg-mesh adopt (--container C \| --config F --image IMG) --host H [--port P] [--dns1 D] [--dns2 D] [--rdp-reject]` | मौजूदा AmneziaWG सर्वर को awg-mesh प्रबंधन में माइग्रेट करें (नीचे देखें) |

## रिमोट मोड (अपने Mac से सर्वर प्रबंधित करें)

```sh
awg-mesh --server my-vps peer list --json   # या: export AWG_MESH_SSH=my-vps
```

लोकल CLI सिस्टम ssh क्लाइंट से `ssh my-vps 'cd ~ && awg-mesh <args>'` चलाता
है (`~/.ssh/config` के एलियास और कुंजियों के साथ) और stdout/stderr/एग्ज़िट
कोड पास-थ्रू करता है — कोई तर्क लोकल रूप से दोहराया नहीं जाता। म्यूटेट करने
वाले कमांड (`init`, `adopt`, `peer add|rename|revoke|rotate`) के बाद रिमोट
`config/peers/` scp से वापस मिरर होता है, ताकि `.vpn` प्रोफ़ाइल आपके लोकल
चेकआउट के पास आ जाएँ। `AWG_MESH_REMOTE_ROOT` सर्वर पर मेश रूट सेट करता है
(डिफ़ॉल्ट `~`)। `skill` और `--version` हमेशा लोकल चलते हैं।

## मौजूदा सर्वर को अडॉप्ट करना

आप पहले से AmneziaWG चला रहे हैं (कोई कंटेनर या हैंड-मेड डिप्लॉयमेंट) और
`awg-mesh` प्रबंधन चाहते हैं — पीयर प्रबंधन, MagicDNS, doctor, मॉनिटरिंग —
**बिना एक भी क्लाइंट प्रोफ़ाइल दोबारा जारी किए**.

```sh
./bin/awg-mesh adopt --container amnezia-awg --host आपका_IP --port 443
# या, होस्ट पर मौजूद कॉन्फ़िग फ़ाइल से:
./bin/awg-mesh adopt --config /root/awg0.conf --image amneziavpn/amneziawg-go:latest \
    --host आपका_IP --port 443
```

क्या **यथावत** ले जाया जाता है (ताकि क्लाइंट को कुछ न पता चले):

| | adopt के बाद |
|---|---|
| सर्वर निजी कुंजी | वही — क्लाइंट वही सर्वर देखते हैं |
| ऑब्फ़स्केशन प्रोफ़ाइल (Jc/Jmin/Jmax/S/H, HeaderProtectionKey, टाइमर) | वही — DPI फ़िंगरप्रिंट अपरिवर्तित |
| पीयर सार्वजनिक कुंजियाँ, PSK | वही |
| पीयर IP | वही — हर पीयर के `AllowedIPs` से लिए गए |
| उपकरणों पर क्लाइंट प्रोफ़ाइल | चलती रहती हैं, दोबारा जारी करना ज़रूरी नहीं |

क्या बदलता है: कंटेनर `amnezia-mesh` compose प्रोजेक्ट के तहत दोबारा बनता है
(`amnezia-mesh-awg` नाम से, dnsmasq साइडकार बन जाता है) और तब से डिप्लॉयमेंट
`awg-mesh` प्रबंधित करता है। विकल्प जो `awg0.conf` व्यक्त नहीं कर सकता, वे
फ़्लैग हैं: `--dns1/--dns2` (MagicDNS फ़ॉरवर्डिंग के लिए अपस्ट्रीम रिज़ॉल्वर,
डिफ़ॉल्ट 1.1.1.1), `--rdp-reject` (RDP UDP/3389 रिजेक्ट नियम), `--domain`
(डिफ़ॉल्ट `awg`)।

कदम-दर-कदम, `adopt`:

1. `awg0.conf` पढ़ता है — कंटेनर के अंदर से (`--container`, इमेज अपने आप
   पहचानी जाती है) या फ़ाइल से (`--config`, `--image` आवश्यक);
2. `[Interface]` + `[Peer]` सेक्शन को `config/server.env` + `config/peers.db`
   में पार्स करता है — अनजान कुंजियों पर **मना कर देता है** (उन्हें सूचीबद्ध
   करके), चुपचाप गिराने के बजाय;
3. `awg0.conf` / `dnsmasq.conf` / `start.sh` रेंडर करके स्टैक चालू करता है;
4. `--container` पर: पुराने कंटेनर को **रोकता** है (कभी नहीं हटाता) और
   `doctor` चलाता है; विफलता पर अपने आप रोलबैक — पुराना कंटेनर दोबारा चालू,
   कुछ नहीं मिटता।

सुरक्षा नियम:

- पुराना कंटेनर सिर्फ़ रुकता है और रोलबैक प्लान के तौर पर होस्ट पर बना रहता है:
  `docker stop amnezia-mesh-awg amnezia-mesh-dns && docker start <पुराना>`
- अनजान `[Interface]` कुंजियों, सर्वर `Address` का सबनेट का पहला होस्ट न होने,
  या `PublicKey`/`PresharedKey` के बिना पीयरों पर adopt रुक जाता है;
- पीयर नाम `# नाम (added …)` कमेंट से आते हैं; बेनाम पीयरों को जनरेट किया हुआ
  `peer-xxxxxx` नाम मिलता है, टकराव पर `-2` सफ़िक्स।

## डिज़ाइन: AmneziaWG वर्ज़न अपडेट क्यों मायने नहीं रखते

1. **AWG इमेज एक सादी निर्भरता है।** `docker-compose.yml` संदर्भ देता है
   `amneziavpn/amneziawg-go` का (`--image` या `AWG_MESH_IMAGE` से ओवरराइड)।
   कुछ भी फ़ोर्क या पैच नहीं किया गया; इमेज टैग बदलने के लिए प्रोजेक्ट में
   कोई बदलाव ज़रूरी नहीं।
2. **सारा तर्क होस्ट पर रहता है।** सर्वर कॉन्फ़िग, dnsmasq कॉन्फ़िग और
   कंटेनर एंट्रीपॉइंट (iptables बूटस्ट्रैप: फ़ॉरवर्डिंग, MASQUERADE, MSS
   clamp, वैकल्पिक RDP-UDP रिजेक्ट) `config/` में जनरेट होकर माउंट होते हैं।
   कंटेनर दोबारा बनाने या अपग्रेड करने पर कुछ नहीं खोता।
3. **इंटरफ़ेस स्थायी UAPI है।** `awg0.conf` के पैरामीटर (Jc/S/H,
   HeaderProtectionKey, टाइमर) AWG प्रोटोकॉल का हिस्सा हैं और रिलीज़ के बीच
   नहीं बदलते। प्रायोगिक `I1`–`I5` (CPS) पैरामीटर `init` पर जाँचे जाते हैं;
   समर्थन रिकॉर्ड होता है और दोनों ही स्थितियों में संगति बनी रहती है।
4. **प्रोफ़ाइल ऐप का नेटिव फ़ॉर्मेट हैं।** `vpn://` प्रोफ़ाइल आधिकारिक
   Amnezia ऐप के एक्सपोर्ट के साथ बाइट-संगत हैं
   (`base64url(uint32_be(len) + zlib(json, 9))`, कॉम्पैक्ट विभाजक — बाइट-दर-बाइट
   सत्यापित)। ऐप के नए रिलीज़ उन्हें इम्पोर्ट करते रहते हैं।

## संरचना

```
docker-compose.yml      awg कंटेनर + dnsmasq साइडकार (साझा netns)
bin/awg-mesh            CLI एंट्रीपॉइंट (पतला शिम, चेकआउट से चलता है)
awg_mesh/               python पैकेज: cli, envfile, peers, keygen, compose,
                        render, profile, doctor, adopt (केवल stdlib)
scripts/                वैकल्पिक मॉनिटरिंग (stats, watchdog, cron)
tests/                  pytest सूट: रेंडर golden फ़ाइलें, peers db + flock,
                        profile कोडेक roundtrip
config/                 जनरेटेड सीक्रेट और स्थिति — gitignore में, होस्ट पर रहता है
```

## मेश कैसे काम करता है (30 सेकंड)

WireGuard क्रिप्टोकी रूटिंग है: हर पैकेट पीयर की सार्वजनिक कुंजी से एन्क्रिप्ट
होता है, और `AllowedIPs` गंतव्य IP को पीयर से जोड़ता है। `100.64.0.4` को ping
करता फ़ोन **हब** की कुंजी से एन्क्रिप्ट करता है — उसे मैकबुक का असली पता कभी
नहीं पता चलता। हब डिक्रिप्ट करके मैकबुक की कुंजी से फिर एन्क्रिप्ट करके
फ़ॉरवर्ड करता है। यह P2P नहीं, hub-and-spoke (रouted मेश) है: यह किसी भी NAT
के पीछे काम करता है, उन carrier-grade मोबाइल NAT सहित जहाँ hole punching
बेकार है। दोनों तरफ़ `PersistentKeepalive=25` NAT मैपिंग को जीवित रखता है ताकि
उपकरण परस्पर पहुँचने योग्य रहें।

## हार्डनिंग नोट्स

- `config/` में निजी कुंजियाँ हैं — यह gitignore में है, मोड 600 है, और सर्वर
  से कभी नहीं निकलती। VPS दोबारा बनाएँ तो एन्क्रिप्टेड बैकअप रखें।
- VPS फ़ायरवॉल default-deny रखें; सिर्फ़ SSH और आपका चुना UDP पोर्ट खोलें
  (443/udp सामान्य HTTPS/QUIC ट्रैफ़िक में सबसे अच्छा घुलता है)।
- ऑब्फ़स्केशन DPI **फ़िंगरप्रिंट** को हराता है, ट्रैफ़िक-मात्रा विश्लेषण को
  नहीं। किसी वैश्विक निष्क्रिय प्रतिपक्ष के सामने यह Tor का विकल्प नहीं है।
- `--rdp-reject` टनल के ज़रिए RDP में मदद करता है (UDP ग्राफ़िक्स चैनल का
  तत्काल TCP फ़ॉलबैक कराता है)। मेश के ज़रिए RDP इस्तेमाल करें तो `init` में
  चालू करें।


मूल इम्प्लीमेंटेशन के बनाए golden फ़ाइलों से बाइट-दर-बाइट होती है, peers db
`flock` सीरियलाइज़ेशन साबित करने के लिए समवर्ती लेखकों से पिटाई खाती है, और
`vpn://` कोडेक roundtrip टेस्ट पास करता है।
