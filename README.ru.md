# amnezia-mesh

Self-hosted WireGuard mesh с обфускацией трафика AmneziaWG, MagicDNS и
профилями exit/mesh в стиле Tailscale — на одном VPS, за ~10 минут и без
зависимостей, кроме Docker.

Представьте «свой собственный Tailscale», но где каждый хоп принадлежит вам:
один небольшой сервер, официальное приложение Amnezia на устройствах и никаких
серверов координации, аккаунтов и сторонних ретрансляторов.

## Возможности

- **CGNAT-сетка** (`100.64.0.0/24`, RFC 6598) — у каждого устройства
  стабильный IP; SSH/ping между устройствами идут через хаб, как `tailscale ssh`.
- **Обфускация AmneziaWG 3.1** — handshake с junk-пакетами, подмена типов
  заголовков, ключ защиты заголовков, случайный padding/trailers. Параметры
  **рандомизируются при каждом развёртывании**, поэтому DPI-фингерпринты у
  разных установок разные.
- **MagicDNS** — dnsmasq на хабе отвечает на `<устройство>.<домен>` (например,
  `laptop.awg`) и форвардит всё остальное в ваш вышестоящий резолвер через туннель.
- **Профили exit + mesh на устройство** — `exit` гонит весь трафик через VPS
  (обход блокировок); `mesh` маршрутизирует только CGNAT-подсеть, интернет
  остаётся напрямую. Оба профиля генерируются для каждого устройства.
- **Нативные профили приложения Amnezia** (`vpn://`) плюс обычные `.conf`
  для любого awg/wg-совместимого клиента.
- **Независимость от версий по дизайну** — образ AWG внешняя, заменяемая
  зависимость; вся логика живёт на хосте (см. «Дизайн» ниже).
- **CLI, дружественный к агентам** — у каждой команды есть вывод `--json`,
  перекрытия через env-переменные и неинтерактивный режим.

## Требования

- VPS с публичным IP, Docker с compose-плагином и `python3`
  (>= 3.8, только стандартная библиотека — никакого `pip install`).
- Открытый UDP-порт в фаерволе VPS (рекомендуется 443/udp — он сливается с
  обычным HTTPS/QUIC-трафиком и его сложнее всего шейпить провайдерам).

## Быстрый старт (человек)

```sh
git clone https://github.com/<you>/amnezia-mesh && cd amnezia-mesh

./bin/awg-mesh init --host ВАШ_IP_ИЛИ_ДОМЕН --port 443
./bin/awg-mesh peer add laptop
# → печатает: config/peers/laptop-exit.vpn, laptop-mesh.vpn и варианты .conf
# импортируйте ссылку .vpn в приложение Amnezia на устройстве

./bin/awg-mesh peer add phone
./bin/awg-mesh doctor      # самопроверка после установки
./bin/awg-mesh monitoring install   # опционально: cron-статистика + watchdog
```

На устройстве: приложение Amnezia → импорт ссылки `vpn://` → подключиться.
Устройства теперь видят друг друга по IP (`100.64.0.x`) и по имени (`phone.awg`).

## Быстрый старт (агент / автоматизация)

```sh
export AWG_MESH_NONINTERACTIVE=1
./bin/awg-mesh --json init --host 198.51.100.10 --port 443
./bin/awg-mesh --json peer add laptop
./bin/awg-mesh --json doctor        # код выхода 0 = все проверки зелёные
```

Вывод — один JSON-объект на команду; при ошибках код выхода ненулевой и
`{"ok": false, "error": "..."}`.

## Команды

| Команда | Описание |
|---|---|
| `awg-mesh init [--host H] [--port P] [--subnet CIDR] [--image IMG] [--domain D] [--rdp-reject]` | Генерация ключей + случайной обфускации, рендер конфигов, запуск контейнеров |
| `awg-mesh peer add <name> [--type exit\|mesh\|both]` | Новое устройство: ключи, IP, профили (применяется через `awg syncconf`, затем контейнер awg перезапускается — один syncconf без рестарта может тихо поломать свежие handshake в userspace-демоне) |
| `awg-mesh peer list` | Устройства, IP, даты создания |
| `awg-mesh peer rename <name> <new-name>` | Переименовать устройство (запись MagicDNS `<name>.<domain>` следует за именем) |
| `awg-mesh peer revoke <name>` | Удалить устройство (конфиг применён, профили удалены) |
| `awg-mesh doctor [--json]` | Docker, контейнеры, listen-порт, ip_forward, MagicDNS, публикация портов |
| `awg-mesh monitoring install\|uninstall` | Cron-статистика (`/var/log/amnezia-mesh-stats.log`) + watchdog |
| `awg-mesh adopt (--container C \| --config F --image IMG) --host H [--port P] [--dns1 D] [--dns2 D] [--rdp-reject]` | Перевести существующий AmneziaWG-сервер под управление awg-mesh (см. ниже) |

## Перевод существующего сервера под управление (adopt)

У вас уже работает AmneziaWG (контейнер или ручной деплой), и вы хотите
управление через `awg-mesh` — пирами, MagicDNS, doctor, мониторингом —
**без перевыпуска ни одного клиентского профиля**.

```sh
./bin/awg-mesh adopt --container amnezia-awg --host ВАШ_IP --port 443
# или из файла конфигурации на хосте:
./bin/awg-mesh adopt --config /root/awg0.conf --image amneziavpn/amneziawg-go:latest \
    --host ВАШ_IP --port 443
```

Что переносится **дословно** (чтобы клиенты ничего не заметили):

| | после adopt |
|---|---|
| приватный ключ сервера | тот же — клиенты видят того же сервера |
| профиль обфускации (Jc/Jmin/Jmax/S/H, HeaderProtectionKey, тайминги) | тот же — DPI-фингерпринт не меняется |
| публичные ключи и PSK пиров | те же |
| IP пиров | те же — берутся из `AllowedIPs` каждого пира |
| клиентские профили на устройствах | продолжают работать, перевыпуск не нужен |

Что меняется: контейнер пересоздаётся в compose-проекте `amnezia-mesh`
(переименовывается в `amnezia-mesh-awg`, dnsmasq становится сайдкаром), и далее
деплоем управляет `awg-mesh`. Необязательные параметры, которые `awg0.conf`
выразить не может — это флаги: `--dns1/--dns2` (вышестоящие резолверы для
форвардинга MagicDNS, по умолчанию 1.1.1.1), `--rdp-reject` (правило reject
для RDP UDP/3389), `--domain` (по умолчанию `awg`).

Пошагово `adopt`:

1. читает `awg0.conf` — из контейнера (`--container`, образ определяется
   автоматически) или из файла (`--config`, требуется `--image`);
2. разбирает секции `[Interface]` + `[Peer]` в `config/server.env` +
   `config/peers.db` — при встрече непонятных ключей **отказывается** (с
   перечнем проблемных ключей), а не молча их теряет;
3. рендерит `awg0.conf` / `dnsmasq.conf` / `start.sh` и запускает стек;
4. если `--container`: **останавливает** старый контейнер (никогда не удаляет)
   и запускает `doctor`; при провале откатывается автоматически — старый
   контейнер стартует обратно, ничего не удалено.

Правила безопасности:

- старый контейнер только останавливается и остаётся на хосте как план отката:
  `docker stop amnezia-mesh-awg amnezia-mesh-dns && docker start <старый>`
- adopt прерывается на неизвестных ключах `[Interface]`, на `Address` сервера,
  не являющемся первым хостом подсети, или на пирах без `PublicKey`/`PresharedKey`;
- имена пиров берутся из комментариев `# имя (added …)`; безымянные получают
  генерированное имя `peer-xxxxxx`, коллизии — суффикс `-2`.

## Дизайн: почему обновления версий AmneziaWG не важны

1. **Образ AWG — обычная зависимость.** `docker-compose.yml` ссылается на
   `amneziavpn/amneziawg-go` (переопределяется через `--image` или
   `AWG_MESH_IMAGE`). Ничего не форкнуто и не пропатчено; смена тега образа не
   требует изменений в проекте.
2. **Вся логика живёт на хосте.** Серверный конфиг, конфиг dnsmasq и
   entrypoint контейнера (iptables-бутстрэп: forwarding, MASQUERADE, MSS clamp,
   опциональный RDP-UDP reject) генерируются в `config/` и монтируются внутрь.
   Пересоздание или апгрейд контейнера ничего не теряет.
3. **Интерфейс — стабильный UAPI.** Параметры `awg0.conf` (Jc/S/H,
   HeaderProtectionKey, тайминги) — часть протокола AWG и не меняются между
   релизами. Экспериментальные параметры `I1`–`I5` (CPS) пробуются в `init`;
   результат записывается, совместимость сохраняется в обоих случаях.
4. **Профили — нативный формат приложения.** Профили `vpn://`
   байт-совместимы с тем, что экспортирует официальное приложение Amnezia
   (`base64url(uint32_be(len) + zlib(json, 9))`, компактные разделители —
   проверено байт-в-байт). Новые релизы приложения продолжают их импортировать.

## Структура

```
docker-compose.yml      контейнер awg + сайдкар dnsmasq (общий netns)
bin/awg-mesh            точка входа CLI (тонкий шим, работает из checkout)
awg_mesh/               python-пакет: cli, envfile, peers, keygen, compose,
                        render, profile, doctor, adopt (только stdlib)
scripts/                опциональный мониторинг (stats, watchdog, cron)
tests/                  pytest-сьют: golden-файлы рендера, peers db + flock,
                        roundtrip кодека profile
config/                 генерированные секреты и состояние — в gitignore,
                        живёт на хосте
```

## Как работает сетка (30 секунд)

WireGuard — это криптомаршрутизация: каждый пакет шифруется на публичный ключ
пира, а `AllowedIPs` сопоставляет IP назначения с пиром. Телефон, пингуя
`100.64.0.4`, шифрует на ключ **хаба** — он никогда не узнает реальный адрес
макбука. Хаб расшифровывает, перешифровывает на ключ макбука и форвардит. Это
hub-and-spoke (маршрутизируемая сетка), а не P2P: работает за любым NAT,
включая мобильный carrier-grade NAT, где hole punching бесполезен.
`PersistentKeepalive=25` с обеих сторон держит NAT-пробитие открытым, поэтому
устройства взаимно достижимы.

## Заметки по укреплению

- `config/` содержит приватные ключи — он в gitignore, с правами 600 и никогда
  не покидает сервер. Если пересобираете VPS — бэкапьте его в зашифрованном виде.
- Держите фаервол VPS в режиме default-deny; открывайте только SSH и выбранный
  UDP-порт (443/udp лучше всего сливается с обычным HTTPS/QUIC-трафиком).
- Обфускация побеждает **фингерпринты** DPI, но не анализ объёма трафика. Это
  не замена Tor против глобального пассивного наблюдателя.
- `--rdp-reject` помогает RDP через туннель (форсирует мгновенный TCP-fallback
  UDP-канала графики). Включите в `init`, если гоняете RDP через сетку.

## Устранение неполадок

| Симптом | Проверить |
|---|---|
| Устройство не подключается | `awg-mesh doctor`; фаервол VPS пропускает UDP-порт |
| Долгое «connecting», затем «connected», но интернета нет | Почти всегда неправильный/устаревший профиль на устройстве: проверьте, какой профиль активен в приложении, удалите старые/тестовые |
| Домены не резолвятся на устройстве | проверка magicdns в `doctor`; в профиле устройства DNS должен быть хабом (генерированные профили так и делают) |
| Низкая скорость | MTU 1280 — намеренно (запас под padding); проверьте steal/CPU на маленьких тарифах VPS |
| `Protocol not supported` от `awg` CLI | известный квирк amneziawg-tools на одиночных запросах ключей; используйте полный `awg show` — косметически |

## Тесты

```sh
python3 -m venv .venv && .venv/bin/pip install pytest
.venv/bin/python -m pytest tests/ -q
```

Сьиту не требует ни Docker, ни сети: рендер серверного конфига сверяется
байт-в-байт с golden-файлами, сделанными оригинальной реализацией; peers db
молотится конкурентными писателями, чтобы доказать сериализацию `flock`;
кодек `vpn://` проходит roundtrip-тесты.
